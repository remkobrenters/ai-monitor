# Desktop acceptance checks

Status: **not yet run**. Automated checks use isolated settings and mocked desktop APIs. They do not prove live GNOME integration.

1. Run `make check`; note any skipped socket integration.
2. Run `./install.sh --dry-run`, then `./install.sh` in a local GNOME terminal. Verify `systemctl --user status ai-monitor.service` is active. Reload Shell or log out/in. Confirm that unrelated extensions and CLI hooks are unchanged.
3. Restart Claude/Codex. In Codex, review/trust the new handlers with `/hooks`. Verify one session per terminal appears even before submitting a prompt; then submit a prompt in each and check working state and project labels. Confirm both icons share one click target and menu. Try `ai-monitor run --name "Navigation test" claude`.
4. Trigger a permission prompt and an explicit question. Verify state labels and a blinking purple background behind only the waiting tool in the panel; no numeric badges should appear there. With blinking disabled, verify the purple highlight stays steady. Finish a turn; verify optional ready alerts. Acknowledge it, wait for an idle notification, and confirm it stays quiet. Submit a new prompt to clear waiting state.

   For Codex, compare automatic review with manual approval. An automatically
   handled permission request should remain Working, including during a long
   command. A real manual prompt or blocking `request_user_input` should alert
   after the three-second confirmation period and next snapshot. Requests resolved
   before confirmation and internal/async question helpers should stay quiet.
   Changing approval routing for a new turn must not reuse the previous turn's mode.
5. Open two Ubuntu Terminal windows and several tabs; click each session and verify the exact window and tab is selected, even though they share one server PID. Close a tracked tab and confirm no unrelated window is raised. In other terminal apps without screen integration, verify the fallback chooser. Rename Claude/Codex sessions and confirm those native names appear with the full working-directory path shown separately. Check that long paths wrap instead of being cut off.
6. Open two tmux windows with multiple panes, and agents in different panes. Click each session. Verify the exact pane/window is selected and the attached terminal is raised. With multiple clients, verify only one client switches. Detach clients; verify the explanatory message. Exit a CLI or kill its pane; verify it disappears.
7. Verify one footer row contains Silent mode, Acknowledge agents, and the settings cog on the right. Silent mode should toggle audio and stay synchronized with the Sound preference, while leaving purple attention indicators enabled. Acknowledge agents should clear current attention, leave session states intact, and allow future questions to alert again; it should be disabled when nothing is waiting. Open Sound settings and verify Effect 1 is selected by default. Preview each effect, choose a custom file and change volume. Check Once, Every minute, and Every five minutes, coalescing, lock suppression, and suppression in the focused terminal tab/tmux pane. Entering that terminal should stop playback; other terminals can still alert. Changing the interval should take effect without restarting.
8. Confirm short/weekly subscription percentages and reset times against each tool. Verify readable Claude/Codex labels and quota bars: green below 70%, orange near depletion, red only when either window is exhausted. Confirm Sessions is above the directly visible token table, without an inner session scrollbar. Confirm the dashboard text matches the theme’s normal menu foreground rather than disabled text. Check that the purple waiting highlight matches the panel hover pill’s height and rounding, including at 200% display scaling. No tagline should remain. Disconnect networking and verify stale indicators. Check cached counts and period totals against sample local records. No missing history should be described as complete annual coverage.
9. After restarting Claude/Codex with the new lifecycle hooks trusted, start several subagents. Verify the parent shows Working with the active count, and a waiting-for-subagents message when it pauses for them. Counts should fall as children finish, without adding terminal rows or triggering input-needed alerts for delegation. A real question/approval should take priority. Verify an interrupted session clears its tracked count. Note any CLI path that fails to emit a start or stop event.
10. Run the installer again. Confirm no duplicated hooks/sessions, retained settings/history, and a healthy service.
11. Add a harmless unrelated hook/setting. Uninstall; confirm that hook/setting remains while ai-monitor's handlers, service, CLI and extension disappear. Reinstall and verify retained history/preferences. Uninstall with `--purge`; confirm ai-monitor history/preferences are removed.

Record GNOME version, Xorg/Wayland, terminal application, CLI versions and observed results. Capture only sample project names when taking screenshots.
